# Architecture rules
- Client/loan list refreshes retain the previous query result while fetching so open loan and payment forms stay mounted and preserve unsaved input.
- Client self-registration uses single-use, expiring, hashed invitation tokens redeemed atomically through narrowly scoped database functions; public callers cannot browse clients or loans.
- Manual and public client registration share field definitions and validation to keep the collected personal data consistent.
- Identity photos belong to clients in private Storage; optional registration uploads and single-use photo-only replacement invitations use token-validated edge functions and atomic redemption. Owner-authorized deletion clears legacy verification and revokes pending photo links; client photos determine verification across loans, while legacy photos remain readable until replaced or deleted.
- Browser push uses a dedicated messaging worker scoped to /push/ (not an app-shell cache), owner-bound subscriptions and server-only VAPID signing derived from a protected seed. The daily callback accepts only fixed requests; service-only atomic database claims enforce its local-time window and one attempt per device/day regardless of caller. Push bodies omit personal financial data.
